# DS-TH09-AI 3.5.0-test 玩家说明

## 本版变化

3.5 基于已验收的 3.4 继续开发，处理灵梦 C1 相关问题，并给 1P AI 接管增加本地配置 key 门槛。原有两侧键位、四项能力参数和默认 2P 接管方式保留。

灵梦 C1 现在区分“预测碰到”与“预计足以起爆”：读取同一个目标的实际血量、受伤状态及固灵状态，结合符札伤害、追踪路径和首次碰撞判断。单张伤害不足不会凭空计整条连爆；前方目标消耗的非贯穿符札不能再次给后方目标计算伤害。未固灵不能直接作为 C1 起爆种子，固灵准备仍须观察到同一目标实际激活，不能只因请求过 Shift 就视为成功。

预测计入剩余充能时间以及符札先展开、后追踪的过程；蓄力后持续复核原来的直接起爆目标。未满 C1 时目标失效可取消，蓄满后只作有界等待，并防止误升 C2。原有期限型 C1 和 C2 的独立规则保留，不把有意的期限释放误报为可靠连爆收益。

新增读取和估计不会改写游戏血量、判定或子弹。避弹与 C 目标继续受同一圆形视野限制，Shift 仍服从实际避弹输出和原来的时间预算。预测只使用当前可见目标及有限时间窗口；目标以后转向、消失、入场或特殊受伤状态仍可能令实际结果不同，本版不承诺每次 C1 必然打爆目标。

## 选择 AI 接管侧

关闭游戏，用记事本编辑 `launcher-settings.json` 中已经存在的 `ai` 对象，保留其他参数。默认字段为：

```json
"side": 2,
"side_key": ""
```

以上是对象内的字段片段，不是完整 JSON 文件；不要新建第二个 `ai` 对象或用片段覆盖整个设置文件。

- AI 在右侧 2P：保留 `"side": 2`，不需要 key。
- 请求 AI 在左侧 1P：设为 `"side": 1`，并把获得的 key 填入同一对象的 `side_key` 字符串。key 区分大小写，不自动去掉首尾空白。
- 请求 1P 时，key 缺失、错误或不是字符串，启动器会提示本次改用 2P AI。原文件中的 `side`、`side_key` 和练习设置保持不变。
- `side` 缺失时按 2P 处理。`side` 本身仍只允许数字 `1` 或 `2`；其他值或字符串 `"1"`／`"2"` 会报错停止启动，不会按 key 回退规则放行。

更改后重新运行启动脚本。以启动控制台显示的**实际接管侧**为准：

| 保存的请求 | key 状态 | 实际 AI 侧 | 玩家侧 | 必须使用 `Charge Type = Slow` 的一侧 |
| --- | --- | --- | --- | --- |
| `side=2` 或未设置 | 不要求 | 2P | 1P | 2P |
| `side=1` | 正确 | 1P | 2P | 1P |
| `side=1` | 缺失／错误／类型不符 | 2P | 1P | 2P |

玩家侧可保留自己的 Charge Type。它与 Key Config 的键盘 Type 是不同设置。

`side_key` 只参与启动器的本地判断，不传入生成的 INI 或 Lua 设置，也不在启动提示和日志中显示。公开默认值为空，代码保存校验摘要。这是**本地配置门槛，不是在线账号授权**；能修改源码的人可以修改或绕过该判断，因此不把它当作远程权限或防篡改机制。

`ai.enabled` 仍然是注意力限制的开关，不表示启用或停用机器人接管。

## 键位和输入隔离

本版不改输入映射：

| 用途 | 左侧 1P | 右侧 2P |
| --- | --- | --- |
| 移动／选人 | 方向键 | W、A、S、D |
| 射击／确认 | Z | J |
| 特殊攻击／取消 | X | K |
| 慢速 | Shift | L |

菜单和选人仍使用这些按键。战斗中仅实际 AI 侧由机器人独占，另一侧由玩家正常操作；机器人达到操作时限后保持停键，不自动交回物理键盘。1P 的 FULL 与 2P 的 LEFT 配置方式沿用 3.4，不要在 AI 运行期间更改 Key Config Type。

## 练习保护跟随实际接管结果

旧字段 `practice.player1_no_damage` 和 `practice.player1_invincible` 始终只表示左侧 1P，没有新增 2P 练习保护。

- 实际 AI 为 2P：1P 是玩家，按保存的配置应用 1P 练习保护，包括请求 1P 但 key 未通过的回退情况。
- 实际 AI 为 1P：自动抑制两个 1P 练习开关的生效，防止保护机器人。原 JSON 值保留，也不会转移为保护右侧玩家。

因此 Slow 模式要求、输入独占和练习保护都按实际接管侧处理，不单看文件里请求的 `side` 数字。

## 原有四项能力设置

| 能力 | 字段 | 默认值与范围 |
| --- | --- | --- |
| 每秒避弹变向上限 | `ai.move_change_budget` | 默认 6，整数 1～10 |
| 自机圆形视野半径 | `ai.vision_radius` | 默认 149.333333333333（448/3），范围 16～640 |
| 注意力容量 | `ai.attention_capacity` | 跟随预设，范围 1～256 |
| 每秒新纳入注意力额度 | `ai.attention_recovery_per_second` | 跟随预设，范围 0.1～256 |

双击 `set-difficulty.cmd` 可以切换预设或调整四项能力；修改和保存难度时保留 `side` 与 `side_key`。切换预设会清除两个手动注意力覆盖，保留视野、变向和其他设置。

默认 `human200` 的注意力容量／新纳入额度为 26／19；`human240` 为 32／24，`human300` 为 40／30，`human480` 为 55／40，`unlimited` 为 120／90。`mech` 默认关闭注意力限制，但仍保留圆形视野和变向上限。预设名称不保证相应的实战存活秒数。

视野以 AI 自机为圆心，采用游戏坐标单位，与窗口像素大小无关。避弹和放 C 的目标、连爆收益及压力判断受同一个圆限制；形状伸入圆内的长激光／长条 EX 仍可见。“每秒”沿用 60 次战斗回调滚动窗口；持续同向移动不重复计数。

## 安装与启动

只支持日文原版 TH09 v1.50a，本包不含游戏。解压时保留整个 `DS-TH09-AI` 文件夹及其中的 `ai`、`runtime`、`source`、`licenses` 和配置文件，把它放在 `th09.exe` 附近的下级目录。启动器向上查找最近的 `th09.exe`，会检查版本；不支持与 thprac、vpatch、Adonis 等注入工具混用。

1. 游戏关闭时编辑 `DS-TH09-AI/launcher-settings.json`，选择 `ai.side`。
2. 双击 `DS-TH09-AI/启动TH09-AI.cmd`。
3. 将选中的 AI 侧 `Charge Type` 设为 `Slow`，玩家侧保留自己的设置。
4. 进入 `Match Mode → 人间 对 人间`，分别选人；开战后 AI 接管配置的一侧。

# DS-TH09-AI 3.3.0-test 玩家说明

本版将视野、注意力和避弹变向上限开放给玩家，暂缓按固定生存秒数标定难度；原预设名称继续兼容。

双击 `set-difficulty.cmd` 打开中文能力设置菜单，可以修改数值、切换预设、保存或放弃修改。下次通过启动脚本启动时生效。

| 设置 | 默认值 | 可调范围 |
| --- | --- | --- |
| 每秒避弹变向上限 | 6 | 1～10，整数 |
| 视野半径 | 149.333333333333 | 16～640 |
| 注意力容量 | 跟随预设；human200 为 26 | 1～256 |
| 每秒新纳入注意力额度 | 跟随预设；human200 为 19 | 0.1～256 |

视野以自机为圆心，默认半径为单侧游戏场地高度 448 的三分之一，使用游戏坐标单位，独立于窗口像素大小。避弹、放 C 的起爆目标、连爆收益与压力判断都只读取圈内对象。只要长激光／长条 EX 的真实当前形状伸进圆内就能看见；圈外对象不会因未来可能飞入而提前可见。已经跟踪的对象离圈后立即退出判断，视野圈随自机移动。自己的气槽、动作门、保护和对手气槽等状态读取保持正常。

“每秒”沿用 60 次战斗回调滚动窗口（正常 60Hz 约一秒），限制被感知危险下的方向切换；持续向同一方向移动不重复计数，平静走位不消耗该预算。原有最短变向间隔继续生效，因此开放到 10。圆形视野约束可用信息，连续移动仍可横穿场地。

注意力容量控制同时跟踪的威胁总成本；每秒新纳入额度控制发现新目标的速度。它们是速度、形状加权的威胁单位，不等于物理子弹颗数。激光、毒云和敌人沿用原有免预算处理，但同样受圆形视野限制。调低注意力会增加漏看，已有压力反馈仍受真实能量和蓄力动作门约束，不保证必放 C 或必定存活。

手动设置的注意力值优先于普通预设；通过菜单切换预设会清除这两个手动覆盖，保留视野、变向和其他设置。mech 默认关闭注意力限制，视野与变向仍有效；不再把 human200／300／480 名称作为存活秒数承诺。

也可在 `launcher-settings.json` 的现有 `ai` 对象中修改：

```json
{
  "difficulty": "human200",
  "move_change_budget": 6,
  "vision_radius": 149.333333333333,
  "attention_capacity": 26,
  "attention_recovery_per_second": 19
}
```

### 操作时限怎样计时

程序按 **AI 战斗回调帧数 ÷ 60** 计算时限，不按系统时钟计时。默认相当于 36000 次战斗回调。达到上限后，AI 释放全部输入，并在本局剩余时间保持停止；下一场重新计时。设为 `0` 时不触发这个停止条件。

暂停菜单期间是否仍调用 AI，由原游戏调度控制，尚未单独验证；不能保证暂停一定停止计时。游戏掉帧时，也不要把这个回调帧预算直接当作现实中经过的秒数。

启动器每次会生成 `ai/runtime-settings.lua` 和 `runtime/ka_ai_duka.ini`。它们是当前路径及设置的生成结果，**不要手动修改**；用户只需编辑 `launcher-settings.json`。

### 窗口使用提示

窗口模式下，把鼠标移到窗口四边或四角即可拖拽。默认 960×720，也可使用 1280×960 等 4:3 尺寸。启动尺寸超出显示器可用区域时，会等比例缩小。

TH09 启动期间可能重建窗口，本包会等待窗口稳定后绑定，并在窗口重建时重新绑定。对同一个窗口，不会不断把用户拖拽后的大小改回 960×720。用户调整的尺寸不自动写回 JSON；下次启动仍使用配置值。

游戏内部仍按原分辨率渲染，放大窗口不会增加画面细节。建议开战前调整大小；拖动旧游戏的窗口时，渲染可能暂时停顿，松开后恢复。全屏模式不提供这种边框拖拽，请先用 `custom.exe` 切回窗口模式。

## 5. AI 默认行为

避弹与射击同时运行。为经营资源而停枪时仍会躲避；操作时限到达或感知失效时才会释放全部输入。

| 场面 | AI 行为 |
| --- | --- |
| 妖精队、灵、可消弹尚未形成有效连爆 | 在高度限制内等待和调整站位，避免过早打散有用队列。 |
| 普通射击／C1目标在更高处 | 不为贴近目标向上追；有限固灵接近仍受Y≥150限制。 |
| 提前C2的净白弹占比低于0.35 | 优先普通射击、C1或等待；独立C2期限不受此门槛影响。 |
| 可以用普通弹引爆有用目标 | 有目的地点射，随后重新观察资源。 |
| 灵群在侧面且捕获链更有价值 | 先高速预靠近，再短低速固灵；受阻或等待到限会退出。 |
| C1适合起爆／接续连爆 | 用可核实的角色覆盖评估收益；当前动作余效与下一次C1分开。 |
| C2已确认生效且有后续资源 | 可请求再按Z；使用真实保护窗口，同时检查到期后的落点。 |
| C2可直接起爆且预计有连爆回能资源 | 通常准备C2；若新C1预计返弹明显更好且未到C2期限，可先用C1。不把C2圈直接吞掉的白弹算作回能。 |
| 连爆资源不足 | 期限前继续养队与避弹，即使因此中弹；期限蓄力可越过资源门槛，危险本身不触发紧急C2。 |
| 距C2期限已近且能量足够 | 提前蓄C2；C1不重置独立C2计时。 |
| 能量不足200但至少100，距任意C期限已近 | 提前蓄C1；独立C2计时继续保留。 |
| Spell Point达到50万 | 不再触发旧版停枪锁，继续依据连爆资源决定射击。 |
| 操作时限到达 | 本局释放全部AI输入，下一场重置。 |

高／低速状态与移动方向分别决定：默认松开Shift养队，只有需要固灵时才短暂低速，不因原地停留就长期按住Shift。用户经验是高速可养三队、低速一队；这是设计依据，尚未逆向核实为完整生成规则。AI没有修改游戏刷怪数量。

未固灵也能被妖精爆风引爆并继续接链，因此会计入传播连接点；普通射击的起爆目标限于妖精等普通敌人和已激活灵。C2直接起爆使用独立条件，能够炸妖精和未固灵，不套用普通枪的对齐要求。

空间资源判断不能只看白弹或灵的总数，还要看妖精队和灵的位置、相邻连接，以及普通枪／C2各自能否启动链条。C2直接消掉白弹与爆风转化白弹是不同结果；争夺包络内白弹保守不计入预期回能或返弹，实际若爆风先到仍可能贡献收益。链距离、圈与爆风竞速和收益仍是启发式估计，会受角色、场面和引擎时序影响，不能保证每次C2后一定能接出下一次C2。

避弹会比较原地不动、慢速与高速的八个方向，使用内存中提供的几何判定、位置和速度做短期预测。这些参数不是通过画面测量，也不会因为窗口放大而同比改变。预测不等于提前知道未来所有招式，所以对持续转向、长期诱导围堵等情况仍可能判断失败。

沿用0.1.8开始的稳定激光ID连续帧跟踪，估计激光起点移动、伸缩、厚度变化和旋转。平移与线性伸缩使用连续相交计算，旋转使用自适应、数量受限的时间区间进行保守扫掠。刚出现、缺少连续历史或超过内部阈值的突然变化，按当前形状处理，不假定已经知道未来；预警转实弹的厚度变化也不会无限外推。游戏标为不可碰撞的魔理沙EX白光发射源，不因为画面很亮就被当作实心障碍。

0.1.9把梅蒂欣毒雾视为会减速的地形，而不是接触即中弹的实心弹。路线预测会使用感知到的有效速度，考虑云的重叠、进入／离开及生效／消散，并评估临时保护消失后的危险。只承认已识别的有效保护状态；避弹会比原始剩余保护提前一次更新恢复危险判断，避免边界误差，不把未知状态当成无敌。开花攻击逻辑使用资源与回充反馈，危险判定本身不改变C等级，也不触发紧急C2。

新原生模块与Lua必须提供匹配且有效的状态快照；缺失、无效或接口版本不匹配时，AI释放全部输入并在启动控制台报错，不回退到忽略毒雾的旧策略。本版没有新增启动器JSON设置，也没有专门的低帧率或时停策略。毒雾路线预测最多分12步；把预测范围调得比默认12更长，会使用更粗的步长，不代表能够同样精细地预知更远的变化。

所有厚度 `height=0` 的激光记录都按软预警处理，短线也不会因此变成真实碰撞。达到 `warning_laser_min_length` 时，程序才额外填充虚拟宽度，尝试提前离开预警线。这是规则处理，不是识别屏幕上所有可见激光图像的保证。

## 6. AI 参数：`ai/config.lua`

时间、窗口与练习保护修改 JSON；避弹、蓄力和调试参数修改 `ai/config.lua`。该文件是 Lua 的 `return { ... }` 配置表，保留花括号、逗号和嵌套结构。修改前先复制一份备份。

配置在每场战斗加载；不在进行中的一场实时刷新。为便于确认，改好后退出游戏并重新启动。表格中的 `dodge.xxx` 表示它位于 `dodge = { ... }` 内，不能直接把带点的字段名粘贴到 Lua 表中。

### 常用参数

| 字段 | 默认值 | 修改影响 |
| --- | --- | --- |
| `dodge.prediction_frames` | `12` | 向前预测的回调帧数，使用正整数。增大可考虑更远的短期威胁，但耗时和对近期运动趋势保持的依赖也会增加，不保证更强。 |
| `dodge.safety_margin` | `4` | 判定附近的额外安全余量。增大更倾向于离危险物远一些，也可能减少可走的狭窄路线。 |
| `dodge.direction_change_cost` | `8` | 身边有危险时，更换移动方向的代价。增大通常更少频繁扭动，也可能让动作更保守。 |
| `debug_log` | `false` | 设为 `true` 记录 AI 决策日志，排查掉帧和行为问题时使用。 |
| `debug_log_interval_frames` | `30` | 每隔多少次回调记录一次日志，使用正整数。越小越详细，写入也越频繁；仅开启日志时有意义。 |

2.0的开花参数在 `bloom = { ... }` 表中，控制空间资源判断、等待、短低速窗口和回充估计。具体字段及默认值以随包 `config.lua` 注释为准，建议先用完整默认配置试玩。原来的 `spell_point_stop`、`spell_point_resume` 和 `charge_weights` 不再控制2.0行为，请勿把旧版配置直接覆盖过来。

开花估计参数不是游戏真实爆炸半径或固定回能公式。调低门槛可能增加释放频率，也可能更早耗尽可供下一轮使用的资源。

### 高级参数

以下项目影响内部评分、几何预测与场地约束。代价通常越大，AI 越不愿选择相应路线；但算法先优先选择预测内没有真实碰撞的候选，再比较评分，不能仅凭某个权重判断最终动作。

| 字段 | 默认值 | 修改影响 |
| --- | --- | --- |
| `dodge.warning_laser_virtual_half_thickness` | `12` | 达到最小长度的零厚度预警线所用虚拟宽度参数。按运行库几何约定计算，不等于放大后画面的像素半宽。 |
| `dodge.warning_laser_min_length` | `36` | 只决定零厚度激光是否额外填充虚拟宽度。所有 `height=0` 激光均为软预警，小于该长度的短线也不会变成真实碰撞。 |
| `dodge.collision_cost` | `100000` | 真实碰撞风险的评分系数；预测越早、接触越久通常代价越高。 |
| `dodge.near_miss_cost` | `140` | 穿过安全余量区域的代价，提高后更倾向于留出间距。 |
| `dodge.warning_laser_cost` | `900` | 进入虚拟激光预警区域的代价。 |
| `dodge.boundary_cost` | `50000` | 预测移动方向会撞到场地边界时的代价。实际预测路线会截在边界，不把越界当成可行逃生路线。 |
| `dodge.wall_margin` | `12` | 距离边界小于此值时，开始增加贴墙代价。 |
| `dodge.wall_cost` | `8` | 贴近边界的惩罚强度。 |
| `dodge.movement_cost` | `0.03` | 移动速度平方的评分系数，倾向于减少没有必要的移动。 |
| `dodge.preferred_x` | `0` | 相对偏好的内部横坐标；0 为本侧场地中间附近。 |
| `dodge.preferred_y` | `320` | 相对偏好的内部纵坐标，不是桌面或视频像素位置。 |
| `dodge.position_cost` | `0.00002` | 偏离上述偏好位置的平方距离代价。提高后更倾向于回到偏好区域。 |
| `dodge.field.min_x` | `-136` | 内部可活动区域的左边界。 |
| `dodge.field.max_x` | `136` | 内部可活动区域的右边界。 |
| `dodge.field.min_y` | `16` | 内部可活动区域的上边界。 |
| `dodge.field.max_y` | `432` | 内部可活动区域的下边界。 |

场地边界与判定尺寸相关参数对应游戏内部坐标，通常不要随意修改。把窗口改成 1280×960 不需要把这些数值乘二。自机高速／低速速度来自游戏内存，没有一个需要跟着显示比例调整的“视觉速度”配置。

建议每次只改一两项，用同样的角色和攻击方式比较效果。若 AI 行为变差，先恢复默认配置，再排查其他因素。

### 开花诊断与边界

2.0.5 CSV共104列，在2.0.4的88列上新增16列：capture_preferred, capture_value, capture_chain_bullets, c1_model_valid, c1_model_limited, c1_chain_bullets, c1_hit_count, common_waves_valid, common_wave_count, can_press_z, c1_action_active, followup_confirmed, followup_z_requests, followup_protection, protected_route_checked, protected_route_collides。

capture列记录独立固灵候选；c1列记录当前可建模范围与链收益估计，model_limited=true表示存在未覆盖部分；共同波列只计观察器接受的已生效、列入更新表的type1圈。can_press_z与can_charge分别表示输入门和蓄力门。followup_confirmed是释放请求与实时变化的策略关联；followup_z_requests单独统计C2后再按Z的请求，不等于额外C1成功次数；followup_protection使用向下取整后提前一更新的保护余量。

protected_route_checked表示执行了保护结束后的落点检查；protected_route_collides表示该检查发现所选落点有预测碰撞。checked=false时不能把collides=false当成已验证安全；未列入CSV的模块返回值另有protected_route_safe、horizon和检测量。所有检查仍依赖有限预测。

既有保护、毒区、激光、高度、实际／建议C2位置、原链准备及形状时序列继续保留。since_c_frames与since_c2_frames按游戏Timer累计；release_c1_requests和release_c2_requests是松Z请求；候选位置收益不是当前位置收益。exit_frames为-1表示没有可靠退出时刻，不能无限等待。正常按配置间隔记录，释放、取消准备及阶段改变时另记事件。资源估计不等于引擎实际返弹、回能或击杀数量。

普通资源规划的C2准备期间会继续复核原连爆链。资源消失时，尚未蓄到C1就取消；处于C1阶段就以C1收手；若快照已在C2区间，沿用的形状规则仅允许对保留链的明确未来改善安全短等；资源失效、白弹将漏过、期限或等级边界结束等待，严格防止进入C3/C4。期限驱动的C2准备越过这项资源复核／取消，但仍受能量与动作门限制。已发出的普通子弹无法收回，场面仍可能在两次观察之间改变。

低速预算统计实际Shift输出，包括避弹必要的低速；供给偏好不会压过真实碰撞约束。固灵邻域、连爆距离和资源分数属于可调策略参数，不是已逆向核验的各角色判定范围。蓄力前瞻按当前蓄力速度估算，并限制为12～60次更新，慢角色的更长周期依靠后续持续复核。

## 7. 日志与反馈

| 文件／信息 | 用途 |
| --- | --- |
| 启动脚本弹出的错误文字 | 游戏版本、路径、缺文件或配置语法问题。启动失败时保留完整文字或截图。 |
| `runtime/native-window.log` | 原生感知、窗口安装、窗口重建、拖拽完成尺寸及练习功能相关信息。 |
| `ai/ai_debug.csv` | 开启 `debug_log` 后生成，记录弹数、选定动作、Spell Point、蓄力状态与决策耗时等。 |
| `VERSION.txt` | 反馈时确认运行包版本。 |

`ai_debug.csv` 会在每场重新创建，重要日志请在下一场开始前复制保存。`dodge_ms` 只表示 Lua 避弹决策耗时，不等于整款游戏一帧的总耗时；导出内存对象和游戏自身渲染也会消耗时间。诊断完成后可以关闭日志。

以下激光诊断列从0.1.8保留，不需要为它们新增配置，`debug_log`默认仍为`false`：

| 日志列 | 含义 |
| --- | --- |
| `laser_count` | 本帧所有子弹记录中的旋转矩形数量，包含远处、没有可跟踪 ID 的记录。 |
| `tracked_lasers` | 同一 ID 有连续前一帧历史、且通过异常跳变检查的激光数；静止激光也计入。 |
| `dynamic_lasers` | 上述可跟踪激光中，起点、长度、厚度或角度至少有一项有效变化的数量，包含远处激光；预警状态切换造成的厚度跳变先忽略。 |
| `laser_sweep_tests` | 动态激光的候选轨迹与时间区间检测次数，平移、伸缩及旋转都可能计入；同一区间的真实碰撞与近失判断合计一次，不是激光条数。 |
| `laser_history_resets` | 连续历史因过大的几何跳变而被弃用的次数；第一次出现、缺帧或消失后重现本身不计为这个重置。 |

0.1.9另增加以下状态／地形诊断列，仍只需打开既有的`debug_log`：

| 日志列 | 含义 |
| --- | --- |
| `sensor_valid` | 原生状态快照是否有效，正常决策行为1。无效时停止输入并在控制台报错，未必写入对应CSV行。 |
| `move_scale_x`、`move_scale_y` | 根据当前毒云与自机位置计算的横／纵移动倍率，不是上一更新的实测位移，也不是屏幕缩放比例。 |
| `protection_frames` | 有效且已识别的保护状态下，原始剩余保护计时值；其他状态为0。内部避弹先向下取整，再减1并至少取0，保守地提前一次更新恢复危险判断。 |
| `can_charge` | 当前状态是否允许正常蓄力，`true`／`false`；不是主动救命或选择C等级的开关。 |
| `charge_block_frames` | 当前攻击动作造成的蓄力受阻剩余计时值，不包含初次按住Z的准备时间。 |
| `poison_clouds` | 通过候选可达范围筛选、且会在预测范围内生效的毒云数，不是场上所有毒云的总数。 |
| `movement_segments` | 本次避弹候选的解析路线段总数，不是实际移动次数；一次候选可能因进出毒区拆成多段。 |
| `player_state` | 原始自机状态编号，供结合原生日志排查；未知状态不会自动获得保护豁免。 |

上述计时值使用游戏内部单位，不是现实秒数。原生日志还应有`player_sensor: install=ok api=1`；出现`player_sensor: install=FAILED reason=...`会阻止启动。安装成功但战斗中快照失效时，AI会放开按键并在控制台报告`player sensor unavailable/invalid`，请连同日志一起保留该错误。

激光历史每次 AI 回调更新，不受日志记录间隔影响。`runtime/native-window.log` 应有 `laser_sensor: install=ok`；若出现 `laser_sensor: install=FAILED reason=...`，启动器会阻止本次游戏继续启动。请保留原因文字，核对游戏版本及完整包，不能只更换 Lua 脚本来绕过原生感知安装失败。

反馈问题时，尽量提供版本号、双方角色、对战设置、是否修改 JSON/Lua、问题发生前做了什么，以及相关日志。掉帧、异常转向或围堵问题可以附一小段录像；窗口与启动问题优先附错误文字和原生日志。

常见检查：

- 找不到游戏：确认启动脚本位于游戏目录的子文件夹里，不要只把快捷方式或个别文件移到别处。
- 版本不匹配：核对上面的原版 EXE 哈希，汉化和第三方改版不支持。
- 两边同时响应按键：确认使用 AI 启动脚本，1P 为 FULL，且未在运行中修改 Key Config Type。
- 不能拖拽：确认处于窗口模式，`window.enabled` 和 `window.resizable` 都是 `true`，查看原生日志是否安装成功。
- AI 战斗中完全停止：先检查 `seconds` 是否已经到期；到期后停止到本局结束是设计行为。
- 控制台提示蓄力模式不支持：把游戏Option中2P的`Charge Type`改为`Slow`，再重新测试；不要改1P的个人设置，也不要与Key Config的键盘`Type`混淆。
- 改了设置不生效：退出游戏再启动；不要修改两个自动生成的配置文件。

## 8. 停用、卸载与恢复键位

退出 AI 启动的游戏后，进程内的 AI、独立读键、练习保护与窗口修补不会继续作用于下一次直接启动的原版游戏。原版 `th09.exe` 文件不会被本包改写。

但启动器可能已经把游戏的 `th09.cfg` 中 **2P Type 保存为 LEFT**。退出或删除 AI 文件夹不会自动还原这一项。直接打开原版游戏时，LEFT 使用原游戏的 Z/X/Shift 与 T/F/H/B 键位，不再是本包的 WASD/J/K/L。

需要恢复安装前配置时：

1. 先退出游戏。
2. 保存一份当前 `th09.cfg`，以免丢掉后来调整的其他选项。
3. 在游戏目录找到启动器生成的 `th09.cfg.before-ai-input-v014-时间.bak`，选择你要恢复的安装前备份。
4. 把该备份复制回同一目录，并以 `th09.cfg` 作为恢复后的文件名。

只有实际需要把 2P 改为 LEFT 时才会生成新备份；如果它原本就是 LEFT，不一定有新备份。没有合适备份时，可在直接启动的原游戏中按个人需要重新设置按键模式。

不再使用时，可删除 `TH09-AI` 文件夹。游戏目录中的配置备份及游戏自己保存的设置、成绩仍会保留；恢复整个 `th09.cfg` 也会同时恢复该备份里的其他选项。请按需要保留，不要把卸载理解为自动撤销所有配置变化。
