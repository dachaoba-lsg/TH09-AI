# DS-TH09-AI 3.5.0-test 使用说明

## 本版变化

3.5 基于已验收的 3.4 继续开发，处理灵梦 C1 相关问题，并给 1P AI 接管增加本地配置 key 门槛。原有两侧键位、四项能力参数和默认 2P 接管方式保留。

灵梦 C1 现在区分“预测碰到”与“预计足以起爆”：读取同一个目标的实际血量、受伤状态及固灵状态，结合符札伤害、追踪路径和首次碰撞判断。单张伤害不足不会凭空计整条连爆；前方目标消耗的非贯穿符札不能再次给后方目标计算伤害。未固灵不能直接作为 C1 起爆种子，固灵准备仍须观察到同一目标实际激活，不能只因请求过 Shift 就视为成功。

预测计入剩余充能时间以及符札先展开、后追踪的过程；蓄力后持续复核原来的直接起爆目标。未满 C1 时目标失效可取消，蓄满后只作有界等待，并防止误升 C2。原有期限型 C1 和 C2 的独立规则保留，不把有意的期限释放误报为可靠连爆收益。

新增读取和估计不会改写游戏血量、判定或子弹。避弹与 C 目标继续受同一圆形视野限制，Shift 仍服从实际避弹输出和原来的时间预算。预测只使用当前可见目标及有限时间窗口；目标以后转向、消失、入场或特殊受伤状态仍可能令实际结果不同，本版不承诺每次 C1 必然打爆目标。

## 选择 AI 接管侧

关闭游戏，用记事本编辑 `launcher-settings.json` 中已经存在的 `ai` 对象，保留其他参数。默认字段为：

```json
"side": 2,
"side_key": ""
```

以上是对象内的字段片段，不是完整 JSON 文件；不要新建第二个 `ai` 对象或用片段覆盖整个设置文件。

- AI 在右侧 2P：保留 `"side": 2`，不需要 key。
- 请求 AI 在左侧 1P：设为 `"side": 1`，并把获得的 key 填入同一对象的 `side_key` 字符串。key 区分大小写，不自动去掉首尾空白。
- 请求 1P 时，key 缺失、错误或不是字符串，启动器会提示本次改用 2P AI。原文件中的 `side`、`side_key` 和练习设置保持不变。
- `side` 缺失时按 2P 处理。`side` 本身仍只允许数字 `1` 或 `2`；其他值或字符串 `"1"`／`"2"` 会报错停止启动，不会按 key 回退规则放行。

更改后重新运行启动脚本。以启动控制台显示的**实际接管侧**为准：

| 保存的请求 | key 状态 | 实际 AI 侧 | 玩家侧 | 必须使用 `Charge Type = Slow` 的一侧 |
| --- | --- | --- | --- | --- |
| `side=2` 或未设置 | 不要求 | 2P | 1P | 2P |
| `side=1` | 正确 | 1P | 2P | 1P |
| `side=1` | 缺失／错误／类型不符 | 2P | 1P | 2P |

玩家侧可保留自己的 Charge Type。它与 Key Config 的键盘 Type 是不同设置。

`side_key` 只参与启动器的本地判断，不传入生成的 INI 或 Lua 设置，也不在启动提示和日志中显示。公开默认值为空，代码保存校验摘要。这是**本地配置门槛，不是在线账号授权**；能修改源码的人可以修改或绕过该判断，因此不把它当作远程权限或防篡改机制。

`ai.enabled` 仍然是注意力限制的开关，不表示启用或停用机器人接管。

## 键位和输入隔离

本版不改输入映射：

| 用途 | 左侧 1P | 右侧 2P |
| --- | --- | --- |
| 移动／选人 | 方向键 | W、A、S、D |
| 射击／确认 | Z | J |
| 特殊攻击／取消 | X | K |
| 慢速 | Shift | L |

菜单和选人仍使用这些按键。战斗中仅实际 AI 侧由机器人独占，另一侧由玩家正常操作；机器人达到操作时限后保持停键，不自动交回物理键盘。1P 的 FULL 与 2P 的 LEFT 配置方式沿用 3.4，不要在 AI 运行期间更改 Key Config Type。

## 练习保护跟随实际接管结果

旧字段 `practice.player1_no_damage` 和 `practice.player1_invincible` 始终只表示左侧 1P，没有新增 2P 练习保护。

- 实际 AI 为 2P：1P 是玩家，按保存的配置应用 1P 练习保护，包括请求 1P 但 key 未通过的回退情况。
- 实际 AI 为 1P：自动抑制两个 1P 练习开关的生效，防止保护机器人。原 JSON 值保留，也不会转移为保护右侧玩家。

因此 Slow 模式要求、输入独占和练习保护都按实际接管侧处理，不单看文件里请求的 `side` 数字。

## 原有四项能力设置

| 能力 | 字段 | 默认值与范围 |
| --- | --- | --- |
| 每秒避弹变向上限 | `ai.move_change_budget` | 默认 6，整数 1～10 |
| 自机圆形视野半径 | `ai.vision_radius` | 默认 149.333333333333（448/3），范围 16～640 |
| 注意力容量 | `ai.attention_capacity` | 跟随预设，范围 1～256 |
| 每秒新纳入注意力额度 | `ai.attention_recovery_per_second` | 跟随预设，范围 0.1～256 |

双击 `set-difficulty.cmd` 可以切换预设或调整四项能力；修改和保存难度时保留 `side` 与 `side_key`。切换预设会清除两个手动注意力覆盖，保留视野、变向和其他设置。

默认 `human200` 的注意力容量／新纳入额度为 26／19；`human240` 为 32／24，`human300` 为 40／30，`human480` 为 55／40，`unlimited` 为 120／90。`mech` 默认关闭注意力限制，但仍保留圆形视野和变向上限。预设名称不保证相应的实战存活秒数。

视野以 AI 自机为圆心，采用游戏坐标单位，与窗口像素大小无关。避弹和放 C 的目标、连爆收益及压力判断受同一个圆限制；形状伸入圆内的长激光／长条 EX 仍可见。“每秒”沿用 60 次战斗回调滚动窗口；持续同向移动不重复计数。

## 安装与使用

保留整个 `DS-TH09-AI` 文件夹，放在支持的日文原版 TH09 v1.50a 游戏目录附近，关闭游戏后编辑设置，再运行 `启动TH09-AI.cmd`。进入 `Match Mode → 人间 对 人间`，确认实际 AI 侧为 Slow 后开始对战。

升级应使用完整匹配版本；不要只替换 Lua 或单个原生模块。保留已有 3.4 及更早 ZIP 作为回退副本。默认操作期限和窗口设置沿用之前版本。

## 诊断与验证范围

调试 CSV 共 169 列，3.4 的前162列顺序不变；尾部新增 C1 准备延迟、伤害模型／战斗快照有效性、血量否决、符札阻挡、锁定种子和等待年龄等信息。反馈时附上双方角色、实际AI侧、Charge Type及本版日志；不要公开包含私人key的设置文件。

本版通过相关 Lua 回归、只读原生快照／x86桥接与双侧挂起测试；原包和独立目录的随包源码重建均须执行发行校验。详细实际数字以本轮交付验证记录为准，不沿用下方历史版本计数。挂起检查不执行游戏主线程，本轮开发验证不等同于实战验收。

目标包：`DS-TH09-AI-v3.5.0-test.zip`。必须整包使用，不混装3.4的原生模块。

DS-TH09-AI 3.4.0-test 使用说明

本版基于 3.3.0-test 增加 AI 接管侧选择。在 `launcher-settings.json` 已有的 `ai` 对象内添加或修改 `"side": 1`（AI 控制 1P）或 `"side": 2`（AI 控制 2P，默认）。保留其他配置，不要再建第二个 `ai` 对象。

| `ai.side` | AI 控制 | 玩家控制 | 必须设为 `Charge Type = Slow` 的一侧 |
| --- | --- | --- | --- |
| `1` | 左侧 1P | 右侧 2P | 1P |
| `2`（默认） | 右侧 2P | 左侧 1P | 2P |

`side` 只接受不加引号的数字 `1` 或 `2`；旧配置没有这一项时按 `2` 处理。非法值会阻止启动并提示修改。关闭游戏后修改，重新运行启动脚本才生效。玩家一侧可保留自己的 Charge Type。

## 按键与输入隔离

接管侧选择不改变两侧按键：

| 用途 | 左侧 1P | 右侧 2P |
| --- | --- | --- |
| 移动／选人 | 方向键 | W、A、S、D |
| 射击／确认 | Z | J |
| 特殊攻击／取消 | X | K |
| 慢速 | Shift | L |

菜单与选人仍由上述物理键操作。进入战斗后，只有配置选中的 AI 侧输入由 AI 独占；另一侧继续响应玩家的物理按键。达到 AI 操作时限后，选中侧仍保持停键，不会自动交还给键盘。AI 代码中的 Z 是射击动作，与键盘上的物理 Z/J 无关。

原来的键盘模式要求保持：1P 使用 `FULL`，2P 使用启动器配置的 `LEFT`；本次进程中的 LEFT 仍映射为 WASD/J/K/L。不要在 AI 运行中修改 Key Config 的 Type。Charge Type 与 Key Config Type 是不同设置。

## 1P 练习保护

`practice.player1_no_damage` 和 `practice.player1_invincible` 始终表示左侧 1P，不会随玩家换侧而改成保护 2P。

- `ai.side=2`：1P 是玩家，两个练习开关沿用原有行为；两者同时开启时以 `player1_invincible` 为准。
- `ai.side=1`：1P 是机器人，为避免给 AI 练习保护，启动器自动抑制这两个开关的实际生效，并在控制台说明；JSON 中保存的值仍保留，切回 `ai.side=2` 时恢复按配置应用。
- 本版没有新增 2P 练习保护。

## 延续 3.3 的能力与策略

避弹、放 C、能量经营、移动限制、圆形视野和注意力参数沿用 3.3；切换接管侧不会改变难度预设。CSV 保持 162 列。继续支持自定义能力，不承诺预设名中的数字等于实战存活秒数。

| 可调能力 | JSON 字段 | 默认与范围 |

| 注意力容量 | `ai.attention_capacity` | 默认跟随预设，范围 1～256 |
| 每秒新纳入注意力额度 | `ai.attention_recovery_per_second` | 默认跟随预设，范围 0.1～256 |

| 预设 | 注意力容量 | 每秒新纳入额度 |
| --- | --- | --- |
| `human200` | 26 | 19 |
| `human240` | 32 | 24 |
| `human300` | 40 | 30 |
| `human480` | 55 | 40 |
| `unlimited` | 120 | 90 |
| `mech` | 默认关闭注意力限制 | 默认关闭注意力限制 |

`human600` 不是当前预设。`unlimited` 仍有有限注意力预算；`mech` 默认只关闭注意力限制，圆形视野和变向上限继续有效。注意力采用速度、形状加权成本，不等于子弹颗数；手动注意力值优先于普通预设。双击 `set-difficulty.cmd` 可调四项能力和切换预设；切预设会清除两个手动注意力覆盖，保留接管侧、视野、变向及其他设置。

视野以 AI 自机为圆心，单位为游戏坐标，与窗口像素大小无关；避弹和放 C 的目标、连爆收益与压力判断均受该圆限制，长激光／长条 EX 的当前真实形状与圆相交即可感知。自己的气槽、动作门、保护及对手气槽读取保持正常。“每秒”指 60 次战斗回调滚动窗口，限制被感知危险中的方向切换；持续向同一方向移动不重复计数，圆形视野也不限制行走距离。

## 安装与启动

只支持日文原版 TH09 v1.50a，本包不含游戏。解压时保留整个 `DS-TH09-AI` 文件夹及其中的 `ai`、`runtime`、`source`、`licenses` 和配置文件，把它放在 `th09.exe` 附近的下级目录。启动器向上查找最近的 `th09.exe`，会检查版本；不支持与 thprac、vpatch、Adonis 等注入工具混用。

1. 游戏关闭时编辑 `DS-TH09-AI/launcher-settings.json`，选择 `ai.side`。
2. 双击 `DS-TH09-AI/启动TH09-AI.cmd`。
3. 将选中的 AI 侧 `Charge Type` 设为 `Slow`，玩家侧保留自己的设置。
4. 进入 `Match Mode → 人间 对 人间`，分别选人；开战后 AI 接管配置的一侧。

不要只更换 Lua 或原生模块；3.4 必须整包使用。不要手动编辑启动器生成的 `ai/runtime-settings.lua` 和 `runtime/ka_ai_duka.ini`，它们会在下次启动时重新生成。

默认操作期限仍是最外层 `seconds=600`，整数 0～86400，0 不限时；按战斗回调/60 计时，分轮不会重新获得一份期限。窗口默认 960×720、可拖动边角并保持 4:3。窗口和练习设置仍可在同一 JSON 中修改。

JSON 不支持注释，末尾不要多加逗号。启用 `ai.debug_log` 可记录 CSV；反馈换侧问题时请同时提供 `ai.side`、双方角色和 Charge Type、`VERSION.txt`、启动控制台文字及相关日志。

# 3.3 及更早版本的历史原文

以下内容完整保留以便追溯旧版本；其中固定“1P 玩家／2P AI”、旧包名、默认值、CSV 列数、测试结果和命令均属于当时版本。3.4 的当前用法、接管侧和练习保护以上文为准。历史说明不能覆盖当前配置。

DS-TH09-AI 3.3.0-test 使用说明

本版将视野、注意力和避弹变向上限开放给玩家，暂缓按固定生存秒数标定难度；原预设名称继续兼容。

双击 `set-difficulty.cmd` 打开中文能力设置菜单，可以修改数值、切换预设、保存或放弃修改。下次通过启动脚本启动时生效。

| 设置 | 默认值 | 可调范围 |
| --- | --- | --- |
| 每秒避弹变向上限 | 6 | 1～10，整数 |
| 视野半径 | 149.333333333333 | 16～640 |
| 注意力容量 | 跟随预设；human200 为 26 | 1～256 |
| 每秒新纳入注意力额度 | 跟随预设；human200 为 19 | 0.1～256 |

视野以自机为圆心，默认半径为单侧游戏场地高度 448 的三分之一，使用游戏坐标单位，独立于窗口像素大小。避弹、放 C 的起爆目标、连爆收益与压力判断都只读取圈内对象。只要长激光／长条 EX 的真实当前形状伸进圆内就能看见；圈外对象不会因未来可能飞入而提前可见。已经跟踪的对象离圈后立即退出判断，视野圈随自机移动。自己的气槽、动作门、保护和对手气槽等状态读取保持正常。

“每秒”沿用 60 次战斗回调滚动窗口（正常 60Hz 约一秒），限制被感知危险下的方向切换；持续向同一方向移动不重复计数，平静走位不消耗该预算。原有最短变向间隔继续生效，因此开放到 10。圆形视野约束可用信息，连续移动仍可横穿场地。

注意力容量控制同时跟踪的威胁总成本；每秒新纳入额度控制发现新目标的速度。它们是速度、形状加权的威胁单位，不等于物理子弹颗数。激光、毒云和敌人沿用原有免预算处理，但同样受圆形视野限制。调低注意力会增加漏看，已有压力反馈仍受真实能量和蓄力动作门约束，不保证必放 C 或必定存活。

手动设置的注意力值优先于普通预设；通过菜单切换预设会清除这两个手动覆盖，保留视野、变向和其他设置。mech 默认关闭注意力限制，视野与变向仍有效；不再把 human200／300／480 名称作为存活秒数承诺。

也可在 `launcher-settings.json` 的现有 `ai` 对象中修改：

```json
{
  "difficulty": "human200",
  "move_change_budget": 6,
  "vision_radius": 149.333333333333,
  "attention_capacity": 26,
  "attention_recovery_per_second": 19
}
```

默认发行配置不写死两个注意力覆盖值，以便切换预设直接生效。手动只设置其中一个时，另一个继续跟随预设。原有 `sight_radius` 是近身威胁相关性参数，新圆形视野参数是 `vision_radius`。

CSV 扩为 162 列，前 149 个字段位置保持，追加视野半径、圈内／圈外对象数、实际变向预算和注意力设置。原始 bullets/enemies/ex_attacks 数量用于诊断对照；field_erasable 及链条收益现在来自圈内快照。保留 3.2.5 的计时、分轮与有界 C1 保蓄优化。

验证：30 套 Lua 回归通过，含硬圆视野 129 断言、玩家参数 12 场景／402 断言、真实主循环视野集成 9 场景／632 断言及 162 列 CSV。Windows PowerShell 5.1 设置菜单 67 项通过；实际 JSON→启动器→runtime→Lua 为 13 场景／413 断言，另有 27 项启动器边界检查。原生构建／自测通过，含 player sensor 58357 项。发行包与随包源码重建验收见最终交付记录。

发行包名称：`DS-TH09-AI-v3.3.0-test.zip`。旧发行包保留，2.0 不变。离线验证不代替实战测试。

DS-TH09-AI 3.2.5-test 使用说明
======================

本版修正开花计时、分轮状态与接近 C2 时的蓄力决策，保留 3.2.4 的视野身份和真实形状修复。

晚期开花的 180 秒现在对应 10800 个游戏 Timer 单位；切入与时停不累计有效时间。CSV 的 battle_seconds 改为真正的游戏秒数，旧日志同名列记录的是 Timer 单位，比较旧数据时须先除以 60。

检测到有效的 state5 分轮信号时，清除上一轮的规划、跟踪与统计缓存；整个接管会话的操作期限继续累计，不因分轮重新获得一份时限。CSV 扩为 149 列，原 134 个字段的名称和位序不变，新字段追加；battle_seconds 的单位修正是明确的语义变化。

C1 接近 C2 时只允许有界等待：必须已经持有蓄力、stock 至少 190，且连续 3 次观察到真实 stock 正增，C2 有用途，并按观测趋势预计 18 个 Timer 单位内能达到 200，才保留这次蓄力短暂等待。回能停止、动作门关闭、暂停、受击或达到等待上限都会退出；只有实际观察到 stock 达到 200 才能升级 C2。趋势不是回能来源或未来收益的保证，不能据此承诺必达 200 或必能保命。

当前 C1 模型把妖精和已固灵作为直接起爆候选；未固灵不能作为 C1 直接种子，但可作为已起爆连通链的潜在爆风中继。几何覆盖、链条收益与回能都不是确认击杀。新增回归约束的是当前模型规则，不证明所有角色真实 C1 都必杀或都不能直接打未固灵。

难度预算、新目标 6 帧纳入扫描设置与移动限制不变：human200 仍为同时跟踪 26／每秒新纳入 19，human300 为 40／30。扫描之间仍逐回调绑定已跟踪对象和刷新当前诊断。200／300 秒是待实战校准目标；本版不调整 2.0 或已有发行 ZIP。

验证：27 套 Lua 回归通过，包括 C1 目标语义 39 断言、分轮与诊断 129 断言、C2 保蓄 25 场景／367 断言、计时与阈值 8 场景／41 断言，以及 149 列 CSV、精简宿主和视野回归。原生构建与自测通过，含 player sensor 58357 项。发行包与随包源码重建的最终校验结果见交付验证报告；离线通过不等于实战存活时间已达标。

发行名称继续使用 DS-TH09-AI，目标文件为 DS-TH09-AI-v3.2.5-test.zip。

DS-TH09-AI 3.1.0-test 避弹难度（人类注意力上限）测试版
======================

作者：圣诞老人的驯鹿-xunlu
完整安装、参数与源码说明请阅读同目录 README.md。
新增代码按 MIT 许可开放；第三方组件适用各自许可，见 licenses/THIRD_PARTY_NOTICES.txt。

3.0第一步在2.0.5已验收基线上加入两件事：能量经营（bloom）模式和只读的对手气槽感知。

bloom模式：自己场上的可消白弹数量达到阈值（默认160）且能量至少200时进入能量经营节奏。进入后C2的独立期限从480游戏Timer缩短到260（约4.3秒），链路门槛放宽为“必须有真实起爆点、净白弹占比≥0.15、敌≥2、净弹≥4、分≥2.5”，成熟蓄力也不再为等形状拖延。压力降到110以下、观察者失效、或连续两个C2周期能量回不到100以上时退出。什么时候进入：基础阈值是自己场可消白弹≥160；对局时间（游戏Timer，切入/时停不计）超过180秒后阈值降到60/40，更早时候若场上可消白弹的平均速度明显上升（自标定+35%）也会把阈值降到90/60；游戏内部rank不读、不猜。这套节奏来自PVP录像（双方每3～5秒复读一次C2，压力越大放得越密、能量越放越多），阈值属于第一版候选值，需要实机标定。

避弹限速（3.0.1）：有危险时每个滑动窗口（默认60次更新）最多改变6次移动方向，两次方向切换之间至少5次更新；超出预算时只能保持原方向或停下（可能因此中弹，这就是模拟人类的弱点）。当这个限制强行改变了更好的逃避选择时，策略会把它当成压力，优先蓄力放C清弹，而不是无限制地微操位。离线合成密集场测得方向切换峰值从17次/秒降到6次/秒。

数据收集版（3.2）：避弹挡位改为按"Lunatic 生存时间"标定（human45/human90/human120/human150/human180/human200 默认/human240/human300/human480/unlimited，mech=关闭限制）。
用包内 set-difficulty.cmd 切换挡位（也可直接改 launcher-settings.json 的 ai.difficulty）。把 ai.debug_log 设为 true 后，每局会单独生成 ai_debug_<挡位>_<时间>.csv（130 列，不会被下一局覆盖），
里面新增 attention_load/attention_budget/attention_skipped/attention_nearest_blind 等"计算依据"列，以及 hit/hits_total（每次被击中都额外记一行）。
3.1 的旧挡位名仍可用：novice=human45、casual=human120、human=human200、veteran=human300、pro=human480。

注意力上限（3.1 引入，3.2 重新标定）：AI不再是"算力无限"，它每单位时间只能精确处理有限个威胁。当前视野里会擦到自己的子弹（sight_radius，默认20游戏单位）按"预计命中时间"排序，最多同时盯住tracked_threat（默认5）个等效威胁、每秒最多新纳入threat_per_second（默认4）个；威胁量按速度折算——标准白弹1.0，快速弹2.0，四季EX"虾条"一根约4.5，激光/毒云/妖精永远可见。没被纳入的子弹不参与避弹计算，所以它可能正好撞上去；连续6帧出现"看不见但即将命中"≥3发时判定算不清，会优先放C清弹，放不出C就只在上下左右/原地这些粗方向里乱动，再不行就挨打。难度全部写在launcher-settings.json的ai段，完整挡位表、成本公式和数据收集方法见同目录 避弹难度挡位.md。

对手气槽：原生只读导出对手的当前／最大气槽、蓄力速度、状态、保护、生命、符点与连击。自己气槽明显多于对手（多100以上）时，bloom进入阈值放宽40点；对手数据无效时按“未知”处理，绝不当作对手没能量，也不会单独触发攻击。形状或数值非法时按部署故障停键并提示。

边界不变：不改避弹几何、不因危险放C、不使用X、不主动C3/C4（仍然只主动C1/C2），不改游戏物理、能量、刷怪与2P保护。当前是可测试交付，尚未实机验收；2.0.5的既有验收不自动适用于本版。

升级请使用完整 DS-TH09-AI-v3.1.0-test.zip，Lua与原生模块必须配套（对手气槽是原生扩展；缺失时Lua仍可运行，但不会得到bloom的放宽条件）。保留2.0.5及更早ZIP作为独立回退副本；打包不会自动替换已安装游戏。

默认600秒操作时限、输入隔离、1P练习与窗口功能、以及3.1新增的避弹难度（ai段，默认human）都在 launcher-settings.json 里；包内该文件是公开默认值，交付时另有"安装-保留设置.ps1"可继承你原来 TH09-AI\launcher-settings.json 的设置。核心apiVersion=1保留，对手opponentApiVersion=1只读子表保留；请整包升级。2P游戏Option的Charge Type必须为Slow；相反模式会停键提示，不自动更改1P设置。

安装
----
1. 把整个“TH09-AI”文件夹复制到 th09.exe 所在目录。
2. 最终目录应类似：

   东方花映塚游戏目录\th09.exe
   东方花映塚游戏目录\DS-TH09-AI\启动TH09-AI.cmd

3. 建议先备份游戏目录中的 score.dat。

路径与移动文件夹
----------------
启动器从自身所在文件夹的上一级开始，逐级查找最近的th09.exe。
允许保留解压外层目录，例如：游戏目录\DS-TH09-AI-v3.0.0-test\DS-TH09-AI。
不会扫描其他文件夹或记住旧安装路径；整个游戏目录移动、重命名后仍可启动。
每次启动都会按当前位置重新生成runtime\ka_ai_duka.ini中的游戏和AI脚本路径，不要手工修改它。
如果相邻目录发现th09.exe但版本不支持，会明确报错，不会跳过它启动更上层的另一份游戏。

启动和选择模式
--------------
1. 双击“启动TH09-AI.cmd”，不要直接运行 th09.exe。
2. 确认Option中2P的Charge Type为Slow，不要与Key Config的键盘Type混淆；1P可保留个人设置。
3. 进入 Match Mode。
4. 选择第一项“人间 对 人间”。
5. 1P由玩家操作；2P角色由AI接管。

选人按键
--------
沿用已校验的游戏硬编码读键修正和战斗输入隔离。
启动器会先备份th09.cfg，保持1P FULL模式，将2P设为LEFT模式；在游戏内存中把LEFT改为独立按键：
* 1P保持原设置（通常是方向键、Z确认、X取消、Shift慢速）。
* 2P使用WASD移动选人，J确认，K取消，L慢速。
* 进入战斗后2P由AI控制。AI代码中的“Z”指射击动作，不受物理键改成J影响。
* 战斗时2P动作由AI独占，玩家物理键不会叠加；达到配置的操作时限后，即使玩家仍按键，2P也保持停止。
* 自动备份在游戏目录，名称为 th09.cfg.before-ai-input-v014-时间.bak。
* 1P须使用FULL模式；若原来是其他模式，启动器会提示，不擅自更改。
* 不要在运行中修改Option的Key Config Type，原游戏菜单认为FULL与LEFT冲突；键位由AI启动器负责。
* 直接运行原版th09.exe不会有内存修补，2P LEFT会恢复原游戏的Z/X/Shift与T/F/H/B；测试请始终用AI启动器。

窗口大小
--------
默认在窗口模式下设为960x720，可用鼠标拖动窗口四边或四角调整大小。
编辑 TH09-AI\launcher-settings.json 可设置 window.width、window.height。
建议4:3尺寸，如960x720或1280x960。屏幕不够大时会等比例缩小。
window.resizable=false 禁止拖动；window.enabled=false 不应用窗口调整。
若当前为全屏，先用游戏的custom.exe切换到窗口模式。
本版在游戏进程内处理边框命中、缩放光标和拖拽消息，默认拖动保持4:3。
window.keep_aspect=false 允许自由宽高比例。建议开战前调好；拖动期间旧游戏可能暂停更新，松开恢复。
游戏启动时可能销毁并重建窗口。本版会等待句柄稳定，安装失败时重试，并在窗口重建后重新绑定。
监视期间不会反复设回960x720，用户拖拽后的大小会保持到该窗口关闭。
修改launcher-settings.json后须退出游戏，再通过AI启动器重新启动。
内部仍为原始分辨率，放大不会增加图像细节。
窗口安装与实际拖拽计数记录在 TH09-AI\runtime\native-window.log。

1P练习设置（默认关闭）
---------------------
编辑 TH09-AI\launcher-settings.json 的practice部分：

   "practice": {
     "player1_no_damage": false,
     "player1_invincible": false
   }

* player1_no_damage=true：1P正常触发受击反应，但每次受击HP完全不变；即使当前只剩1HP也不会扣血，并非扣血后保底到1HP。
* player1_invincible=true：1P接触危险物时仍会断Spell Point连击，但不触发正常受击反应，也不扣生命。
* 两项均为false时使用正常受击规则；两项同时为true时，以player1_invincible为准。
* 两项只保护左侧1P玩家，不保护右侧2P AI，不改变AI的避弹、蓄力或操作时限规则。
* 修改后须退出游戏并重新运行AI启动器；只在本次AI启动的游戏进程中生效。
* 即使window.enabled=false，练习开关仍可单独生效。
* 不要同时使用thprac注入本游戏，避免双方修改同一处代码或窗口过程。

AI行为
------
* 使用游戏内存中的子弹、激光、敌人、EX攻击和自机判定进行短期连续轨迹避弹。
* 0.1.9只读感知中毒有效速度及临时保护/回充状态，将梅蒂欣毒雾作为减速地形，并考虑保护结束后的危险。
* 只承认有效且已识别的临时保护，避弹比原始剩余保护提前一次更新恢复危险判断；未知状态不当作无敌。
* 缺失/无效或接口版本不匹配的状态快照会使AI释放全部输入并在控制台报错，不回退到忽略毒雾的旧策略。
* 0.1.8按稳定ID关联激光连续帧，预测判定起点、长度、厚度和角度变化；旋转使用自适应、数量受限的时间区间进行保守扫掠，普通弹继续走快速连续轨迹路径。
* 魔理沙EX的不可碰撞白光发射源不作为实心弹处理；零厚度激光仍是软预警，不当作已生效的真实碰撞。
* 0.1.3用连续碰撞区间替代逐帧重复碰撞调用；扫描全部物体，没有按数量丢弃子弹。
* 优先选择预测期内不撞弹的方向，加入转向稳定代价，仍可能被长期诱导围堵击中。
* 等待妖精队、灵和可消弹形成有用空间链，再选择普通射击、C1或C2点燃；不按全场总数直接决定释放。
* C2可以直接炸妖精／未固灵起爆；C2直接吞白弹没有回能或返弹收益，不能只看总消弹量。
* C2资源条件合适时优先，C1也可主动经营连爆；只主动蓄放C1/C2。游戏分数自然触发攻击不等于AI主动C3/C4。
* 默认松开Shift高速养队，按需短低速固灵；原地不动不等于需要低速。高速三队／低速一队是用户经验，尚未逆向确认为生成公式。
* 依据资源和回充反馈规划C2；期限前可等待到中弹，期限准备可越过资源门槛。C2独立8秒计时不被C1重置，缺C2能量时按任意C计时安排C1；危险不触发紧急C2。50万停枪锁已删除。
* 每场战斗达到配置的操作时限后，永久释放全部AI输入，直到下一场重新计时；默认600秒，设置为0可不限时。
* AI永远不会发送X键，不会使用“命中前一帧紧急释放全部能量”的内置AI行为。
* 对C3诱导弹只做短期局部避弹，因此仍可能被多组诱导弹围死。这是预期弱点。
* 所有height=0激光均为软预警，包括短线；warning_laser_min_length只决定是否额外填充虚拟宽度，不会把短线变成真实碰撞。

修改设置
--------
操作时限、窗口、1P练习设置和避弹难度统一编辑：

   TH09-AI\launcher-settings.json

seconds位于JSON顶层，与window、practice、ai同级，例如：

   "seconds": 600

seconds必须为0到86400的整数，默认600；0表示不限时。

避弹难度在ai段（3.1新增），例如：

   "ai": { "difficulty": "human" }

difficulty可选 mech / pro / veteran / human / casual / novice：
mech关闭注意力限制（等于3.0.1的避弹行为），human是默认的"一般人"水平。
也可以只改一个数字，例如 "threat_per_second": 3.0 表示每秒只能新看清3个等效威胁（比默认更弱）。
数字会覆盖挡位预设；完整挡位表、成本公式和调参方法见同目录 避弹难度挡位.md。
按AI战斗回调帧数除以60计时，而不是系统时钟；达到上限后释放全部AI按键，本局不再恢复，下一局重新计时。
暂停菜单期间是否仍调用AI由原游戏调度控制，目前尚未单独验证，不承诺暂停必定停计。
修改JSON后须退出游戏，再重新运行AI启动器。
启动器每次会生成 TH09-AI\ai\runtime-settings.lua，不要手动修改这个生成文件。

避弹和射击策略仍用记事本编辑：

   TH09-AI\ai\config.lua

常用项目：
* bloom = { ... }：开花空间资源、等待、固灵窗口和回能估计，字段默认值见config.lua注释。
* dodge.prediction_frames = 12（位于dodge表内）
* dodge.attention = { ... }：3.1注意力上限的默认值（正常玩法请改launcher-settings.json的ai段，不要改这里）。
* debug_log = false（也可以在launcher-settings.json的ai段里用 "debug_log": true 打开）

先使用默认配置测试不同角色。连爆范围和回能估计是策略启发式，不是游戏真实公式。
spell_point_stop、spell_point_resume、charge_weights已不再控制2.0行为，不要直接覆盖旧config.lua。

### 开花诊断与边界

2.0.5 CSV共104列，在2.0.4的88列上新增16列：capture_preferred, capture_value, capture_chain_bullets, c1_model_valid, c1_model_limited, c1_chain_bullets, c1_hit_count, common_waves_valid, common_wave_count, can_press_z, c1_action_active, followup_confirmed, followup_z_requests, followup_protection, protected_route_checked, protected_route_collides。

capture列记录独立固灵候选；c1列记录当前可建模范围与链收益估计，model_limited=true表示存在未覆盖部分；共同波列只计观察器接受的已生效、列入更新表的type1圈。can_press_z与can_charge分别表示输入门和蓄力门。followup_confirmed是释放请求与实时变化的策略关联；followup_z_requests单独统计C2后再按Z的请求，不等于额外C1成功次数；followup_protection使用向下取整后提前一更新的保护余量。

protected_route_checked表示执行了保护结束后的落点检查；protected_route_collides表示该检查发现所选落点有预测碰撞。checked=false时不能把collides=false当成已验证安全；未列入CSV的模块返回值另有protected_route_safe、horizon和检测量。所有检查仍依赖有限预测。

既有保护、毒区、激光、高度、实际／建议C2位置、原链准备及形状时序列继续保留。since_c_frames与since_c2_frames按游戏Timer累计；release_c1_requests和release_c2_requests是松Z请求；候选位置收益不是当前位置收益。exit_frames为-1表示没有可靠退出时刻，不能无限等待。正常按配置间隔记录，释放、取消准备及阶段改变时另记事件。资源估计不等于引擎实际返弹、回能或击杀数量。

普通资源规划的C2准备期间会继续复核原连爆链。资源消失时，尚未蓄到C1就取消；处于C1阶段就以C1收手；若快照已在C2区间，沿用的形状规则仅允许对保留链的明确未来改善安全短等；资源失效、白弹将漏过、期限或等级边界结束等待，严格防止进入C3/C4。期限驱动的C2准备越过这项资源复核／取消，但仍受能量与动作门限制。已发出的普通子弹无法收回，场面仍可能在两次观察之间改变。

低速预算统计实际Shift输出，包括避弹必要的低速；供给偏好不会压过真实碰撞约束。固灵邻域、连爆距离和资源分数属于可调策略参数，不是已逆向核验的各角色判定范围。蓄力前瞻按当前蓄力速度估算，并限制为12～60次更新，慢角色的更长周期依靠后续持续复核。
