# 参与 TH09-AI 2.0.6

请把改动限制在本仓库对应的版本。三个源码快照拥有不同的策略和配置，不能仅凭版本号相近就直接替换另一代的 Lua、原生模块或默认设置。

## 提交改动

1. 先阅读 [README.md](README.md) 的当前行为，再按 [BUILDING.md](BUILDING.md) 准备环境。
2. 修改可维护的源文件：Lua 在 `src/ai/`，原生代码在 `src/native/`，启动器在 `src/launcher/`，玩家配置和文档模板在 `package/`。不要把 `dist/` 里的生成文件当作唯一修改位置。
3. 为行为修复补充能复现问题的回归用例，运行 `python tests/run_all_lua.py`。涉及原生代码、启动脚本或发行结构时，再运行完整源码构建与包验收。
4. 说明问题的触发条件、修改后的行为、测试命令与结果，以及尚未验证的实战部分。提交前检查 `git diff` 和 `git status --short`。

不要为了让测试通过而改写游戏物理、2P HP、能量或碰撞结果。预测资源、输入请求和观察到的成功结果应继续区分；新的日志字段需明确单位和兼容关系。

保留 Windows PowerShell 5.1 需要的脚本编码、中文/空格路径处理和第三方许可。更新依赖时同时更新固定来源、哈希和相关说明，不要无校验地追随上游最新版本。

## 报告问题

请提供版本、游戏版本、角色与难度、可复现步骤、预期和实际行为。涉及能力参数时附上相关设置。能提供关键时间点、短录像或日志片段会更容易定位；先检查并移除个人路径或其他私人信息。

分清以下几种结果：构建/离线回归通过、启动配置验证通过、真实对战验证通过。单次录像或离线测试不能证明固定存活秒数、所有角色 C1 必杀、稳定回能或全场绝对安全。

## 源码与发行文件

`work/`、`vendor/`、`downloads/`、`dist/` 为本地生成目录；游戏本体、录像、调试日志和运行时生成的 INI/Lua 配置不应进入源码提交。不要用强制添加绕过这些排除规则。需要发布玩家可用版本时生成完整 ZIP，并保留包内源码和第三方材料。

原创修改沿用 [LICENSE.txt](LICENSE.txt)；第三方源码、运行库和对应源码材料保留各自许可。修改本项目不能重新授权上游文件。请勿在问题报告或提交中附带游戏本体。
