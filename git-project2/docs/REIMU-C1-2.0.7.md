# 2.0.7：灵梦 C1 的击破与连爆判断

基线为 2.0.6。开发评测录像中，左侧 1P 的灵梦是分析对象。本版保留 2.0.6 的 C2 节奏和避弹，仅补充灵梦 C1 的判断依据。

## 录像能说明什么

- 约 278.00～278.50 秒：低位符札效果消失，得分未见变化，妖精队继续移动，没有看到相应的大连爆。
- 约 109.60～110.50 秒：符札先在低位停留，随后向上；出现小规模命中／爆炸，而右上妖精横队继续移动。当前画面看起来能覆盖，不等于符札抵达时还能接到整队。
- 约 282.25～282.75 秒：符札接近妖精和已有爆风后出现多处爆炸，但已有爆风也可能参与，不能全部归因于这发 C1。

录像没有逐帧按键、实体 ID 和 HP，不能单凭这些画面断定“完全没按 Shift”或“必定差多少伤害”。以下修复由录像现象、当前源码和日文原版 1.50a 的静态机制共同支持。

## 2.0.6 的判断缺口

灵梦使用自定义符札运动回调，旧通用直线 C1 模型不支持它；策略有时会退回普通射击的连爆评分。已有符札则可能仅因矩形接触目标，就把目标所在连通组记作可起爆。两种路径都缺少“这一发是否足以打死目标”的判断。过高的 C1 评分还会压过原本有价值的固灵准备。

此外，多张符札在同一位置时，按几何去重可能把独立攻击合并，低估可用伤害；只按释放时的白弹分布计收益，则会高估迟到符札的返弹机会。

## 本版怎么改

1. **读取目标事实。** 在原生敌人导出表上追加只读 `enemy.sensor`：HP、当前碰撞／受伤门、伤害除数、主碰撞框和有限模型标记。字段绑定原生实体，不按屏幕位置猜身份。
2. **按灵梦符札估算击破。** 核实 selector 1 为四张非穿透符，每张基础伤害 30、初速 0.5、48×48 判定；整数 Timer 到 40 后才进入追踪更新。最多预测 90 次正常时间更新，包含实际蓄力／暖机的释放等待；保留当前已读追踪目标，不凭空假设未来会选中低血量目标。
3. **接触不等于击破。** 同帧命中先累加伤害，再按目标除数取整；不同帧分别结算。无伤目标仍可挡掉非穿透符。HP 不足以打死、不明伤害门或未知额外碰撞框，都不能提供主动 C1 的击破依据。多张重叠符按原生槽位区分。
4. **先固灵，再确认。** 未激活灵不能作为 C1 直接起爆点，但仍可传播妖精／其他目标的爆风。主动 C1 缺乏击破依据时，保留短 Shift 固灵或普通射击经营；按住 Shift 本身不冒充已经激活，必须等到对应实体的实际状态变化。
5. **按预计击破时刻计资源。** 把原连通组和白弹移到符札命中时再估算。提前漏走的白弹不算；新来的无关妖精／灵不能接替原链；同一实体被较早连爆消费后，不能在较晚符札命中时再次贡献爆炸。不同事件中的同一白弹只计一次。
6. **限制计算量。** 先用目标的移动包围框筛选符札可能碰到的对象，再做逐更新矩形检查；过大的移动范围走有界保守扫描，避免漏掉挡符目标。

已经生成的符札仍只使用当前可确认的矩形接触，不将整个发射模板重新算成下一发 C1。时间停止／非正常倍率下不套用这份正常时间追踪预测。血量、追踪和连爆估算都可能在下一帧改变，策略会重新核对；未蓄到 100 时可取消失去依据的主动 C1。

## 保留的行为与边界

- 原 260／200／480 游戏 Timer C2 节奏、C1 不重置 C2 计时、只主动 C1/C2、无 X、高度 Y≥150、毒／激光避弹和 C2 后路线不变。
- C2 直接吞白弹仍不计返弹或回能。连爆半径、传播和能量仍是策略估算，不是完整引擎模拟。
- 到期限的 C1、已经蓄成后的松 Z，以及 C2 计划失效后的物理释放，可能仍放出无理想目标的 C1。本版没有承诺每一发都击破。
- 不通过持续低速换取固灵，继续保留高速妖精队供给与实际 Shift 预算。
- 必须使用完整 2.0.7 包，Lua 与原生 DLL 配套。2.0.6 及旧 ZIP 保留。

## 验证与后续验收

新增灵梦血量／减伤／挡符／延迟／原链消费的观察器专测，及固灵反馈、主动 C1 取消、等待上限和期限例外的策略专测。真实 observer→policy→dodge 整合用例验证：未激活时先固灵；仅 Shift 经过若干帧不会凭空解锁；收到激活和足够伤害信息后，才开始 C1。

最终离线验证通过：21套 Lua（灵梦观察406、策略203、整合113项检查）；原生61074项；真实x86导出12场景；4组挂起初始化。原包与全新目录随包源码重建各246项检查／63条目通过，两份运行Lua的专项回归通过，17个旧ZIP未变。公开复验入口见 [构建说明](../BUILDING.md)，新增测试为 `tests/reimu_c1_observer_test.lua` 与 `tests/reimu_c1_policy_test.lua`。

性能微测为 64 位 Lua 合成输入，不含实际 32 位注入、原生扫描或游戏渲染；不能承诺密集场景 60 FPS。

本版仍需实战验收。建议观察同样的灵梦场景：符札抵达前是否先经营灵／妖精形状、无法击破时是否减少空 C1、上方白弹是否更常通过连爆返回。CSV 现为 113 列，新增 `c1_damage_model_valid`、`c1_kill_count`、`c1_contact_count`、`c1_kill_delay`；后三者是预测，不是实际击杀日志。`kill_delay` 从当前时刻包含蓄力、暖机和飞行，零不表示一定命中。
