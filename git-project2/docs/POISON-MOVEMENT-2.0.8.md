# 2.0.8：开花机兼容毒优化

本版基于2.0.7，只增加毒中移动方向的偏好。固灵、普通射击、连爆规划、灵梦C1判断、C2节奏和C2后的阶段路线继续使用原算法。

## 浓度怎样判断

按原生快照中**实际生效且覆盖机体中心的毒云层数**判断，不按画面颜色深浅猜。原有运动预测仍按每层约乘0.4计算减速；新策略不会改游戏移速或毒效果。比如二层毒的有效倍率约0.16，一层约0.4，脱离后恢复非毒的基础倍率。

只有当前已经在生效毒雾内、感知有效且游戏处于正常时间倍率／允许移动时，才启用新偏好。机体中心不在生效毒云覆盖范围、云尚未生效或已过期、切入／时停或关闭开关时，沿用原来的选路。

## 如何选方向

继续生成原来的移动候选并计算弹幕碰撞、真实减速、墙、高度和C2保护结束时的安全性。然后在合格候选中依次比较：

1. 默认12更新预测路径中的平均毒层数，优先让整段路少受毒。
2. 预计终点的毒层数，优先由多层进入少层或出毒。
3. 如果短距离内层数都不变，选择更靠近最近一层毒云边界的方向，避免在毒深处完全不动。
4. 上述指标相同时，继续按原开花站位、方向惯性等评分决定。

第三项只是短距离的出圈方向提示。单朵毒云内的实际减速不会随离中心远近连续变化，也不承诺该边界之后一定有一条长期安全通路。路径采样最多12次，与原毒中运动预测的有界步数对应；它不是任意长时间的全局寻路。

## 不会为了低毒牺牲什么

- 有无碰撞路线时，不选择预测会中弹的路线；保留墙、高度限制和已有C2保护结束后的落点检查。
- 使用原几何选择的同一小幅软风险预算，开花和低毒偏好不会各用一次预算后叠加放宽。
- 保留原开花／避弹选出的Shift状态，只在这个高／低速状态下比较方向。因此可以一边按计划固灵，一边朝低毒方向移动；不会因逃毒擅自加低速、取消固灵或改变C等级。
- 如果所有路线都会碰撞，或当前保护结束检查没有合格落点，保留原避弹排序，不把“毒少”误当作“安全”。

## 设置与诊断

默认开启：`ai/config.lua` 的 `dodge.poison_escape_enabled = true`。设为 `false` 可与原2.0.7选路对照；配置在下一场加载。

CSV由113列扩展到118列，新增：

| 字段 | 含义 |
| --- | --- |
| poison_preference | 本次是否实际启用低毒选路比较 |
| poison_layers_now | 当前覆盖的有效毒云层数；未做有效评估时为0 |
| poison_layers_end | 所选短路径终点的预计毒层数 |
| poison_exposure | 所选路径采样得到的平均毒层数 |
| poison_escape_changed | 相对于本次原开花／避弹选择，低毒偏好是否改变了按键方向 |

解释终点和平均层数时，先看`poison_preference`是否为true。这些是预测和策略输出，不是已经脱毒的实测记录。

## 验证与实战范围

新增单层、叠层、深层亚像素移动、生命周期、Shift保留、危险／墙／高度优先、保护到期与随机场景测试，并保留全部开花、灵梦C1、毒减速、激光和主循环回归。

此前 2.0.8 开发交付记录：23 套 Lua 通过，毒偏好专项 5972 项、性能专项 2552 项；原生自测通过，原包与独立随包源码重建各 246 项检查／63 条目通过，并校验既有开花策略、观察器和原生源码保持。此处为历史开发证据，不表示本次公开源码同步重新执行了全部验证；不公开私有开发交接和日志，也不据此宣称用户已实战验收。公开构建与重跑方式见 [BUILDING](../BUILDING.md)。

离线通过不等于任何密集毒阵都能脱离：严重减速可能使安全出口不可达，原短程避弹也不能保证长期围堵中的生存。实战可重点观察同样的毒阵中，机体是否逐步从叠层区向薄毒／无毒区移动，同时继续原来的固灵和C2连爆节奏。
